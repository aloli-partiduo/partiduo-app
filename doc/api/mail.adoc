= Socle : envoi de courriels
:toc: left
:toc-title: Table des matières

Envoi de courriels par une extension (A-REP-2, contrat 0.16.0) : documents
d'un listing, avis, rapports. Contrat `Partiduo::Api::Mail`
(`src/core/api/mail.cr`) ; transport `Partiduo::Core::Mail`
(`src/core/services/mail.cr`).

== Transport de l'instance

Un seul transport pour tout le dossier, réglé par l'instance :

* `PARTIDUO_SMTP_URL` : `smtp://utilisateur:secret@hôte:587?security=starttls`
  (`none`, `tls`), `smtps://hôte:465` (TLS direct), `helo=` facultatif ;
  sans elle, aucun envoi (`DisabledTransport`) ;
* `PARTIDUO_MAIL_FROM` (facultative) : adresse d'expédition imposée par
  l'instance (domaine autorisé par le serveur SMTP) ; sinon l'adresse
  électronique de la société.

La Facturation (envoi des documents et des relances) utilise le même
transport : il était le sien et a rejoint le socle ; ses noms
(`Partiduo::Invoicing::Mail::MemoryTransport`, `Api::Invoicing.mail_transport`…)
restent valables. En specs (`MARTEN_ENV=test`), le transport par défaut
n'est jamais SMTP ; les specs capturent les messages :

[source]
----
transport = Partiduo::Core::Mail::MemoryTransport.new
Partiduo::Core::Mail.transport = transport
# … transport.messages ; transport.failure = "550 …" simule un refus
Partiduo::Core::Mail.transport = nil  # revient au défaut
----

== Contrat

[cols="2,1,3",options="header"]
|===
|Appel |Droit |Rôle

|`deliver(actor, MessageInput, module_code) : Result(MessageView)`
|authentifié au niveau exigé ; pièce `module_code` active
|Journalise le message (`queued`) dans la transaction de l'appel et
l'envoie à sa validation (`Events.after_commit`) : rien ne part d'une
opération annulée. Appelé hors transaction, le message est déjà parti au
retour (`sent` ou `failed`). L'appelant vérifie d'abord son propre droit.

|`message(actor, id) : MessageView`
|son auteur, ou `core.settings.manage`
|Un message journalisé ; `NotFound` sinon.

|`messages(actor, module_code = nil, limit = 100, offset = 0)`
|`core.settings.manage`
|Journal, du plus récent au plus ancien.

|`configured?(actor) : Bool`, `sender(actor) : String?`
|authentifié
|Transport configuré ; adresse d'expédition imposée.
|===

`MessageInput` : `to`, `subject`, `body` (texte), `cc`, `attachments`
(`AttachmentInput` : nom, type, contenu), `attachment_ids` (pièces du
socle, droit `core.attachment.read`). Les adresses peuvent être séparées
par des virgules ou des points-virgules ; les doublons sont retirés.

Expéditeur : `PARTIDUO_MAIL_FROM` ou l'adresse de la société, au nom de la
société ; si l'adresse d'expédition n'est pas celle de la société,
`Reply-To` la donne. L'appelant ne choisit pas l'expéditeur.

Limites : 50 destinataires (À et Cc), sujet de 255 caractères (caractères
de contrôle retirés), corps de 100 000 caractères, pièces jointes de 20 Mio
en tout.

Refus (`core.errors.mail.*`) : `to.blank`, `to.invalid` (`%{address}`,
champ `to` ou `cc`), `to.too_many`, `subject.blank`, `subject.too_long`,
`body.too_long`, `attachments.too_large`, `attachments.filename`,
`no_sender`, `not_configured` (champ `base`).

`MessageView` : `id`, `module_code`, `sent_by_id`, `sender`, `reply_to`,
`to`, `cc`, `subject`, `attachments` (noms), `message_id`, `status`
(`queued`, `sent`, `failed`), `error`, `created_at`, `sent_at`, `sent?`,
`failed?`.

== Journal

Table `core_mail_message` (migration core 0006) : pièce, auteur,
expéditeur, réponse, destinataires, sujet, corps, pièces jointes (nom et
empreinte SHA-256, pas le contenu), identifiant du message, état et refus
du transport, dates. Un envoi refusé par le transport reste `failed` avec
son motif ; il n'y a pas de nouvel essai automatique : l'appelant renvoie.

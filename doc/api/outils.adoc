= Contrat du cœur — outils : imports CSV, export du plan, archive des pièces
:toc: left
:toc-title: Sommaire

Outils que l'ADR-003 déclare absorbés par le cœur (table « Sort des
extensions amont » : import de fiches, outils du plan comptable, outils
divers). Décisions : DECISIONS `D-OUT-001` à `D-OUT-008`. Source
fonctionnelle : les extensions legacy d'import de fiches, du plan comptable
et d'outils comptables ; le code n'est pas repris.

== Parcours commun des imports (`Partiduo::Api::Core`)

Un import se fait en deux temps, sans fichier temporaire côté serveur :

. *aperçu à blanc* (`preview_*`) : chaque ligne passe par la commande
  ordinaire du contrat (création ou modification), avec tous ses contrôles,
  dans une transaction annulée à la fin (`Transaction.dry_run`) ; la vue
  donne la suite prévue de chaque ligne ou les motifs de son refus ;
. *import* (`import_*`) : le même traitement dans une seule transaction.
  Rien ne passe d'office : une ligne refusée fait échouer l'import
  (`core.errors.import.has_refused`, pluriel par `count`) et rien n'est
  enregistré, sauf si l'appelant confirme explicitement d'écarter les
  lignes refusées (`skip_refused: true`).

[cols="2,4",options="header"]
|===
|Type |Rôle

|`CsvFormat(separator = ';', quote = '"', encoding = "utf-8", skip_rows = 0)`
|Séparateurs `CSV_SEPARATORS` (`;` `,` tabulation `\|`), délimiteurs
`CSV_QUOTES`, encodages `CSV_ENCODINGS` (`utf-8`, marque d'ordre retirée ;
`windows-1252`). 5 Mo et 10 000 lignes au plus.

|`ImportSource(content : Bytes, format, columns : Array(String)? = nil, update_existing = false)`
|`columns[i]` : clé du champ de la colonne `i`, `""` pour l'ignorer ; `nil` :
en-tête reconnu dans la première ligne (clés ou libellés des champs, en fr,
en ou nl, accents et casse ignorés), sinon association par défaut de
l'import. `update_existing` : une ligne qui désigne un enregistrement
existant le met à jour (cellules non vides seulement) au lieu d'être
refusée.

|`ImportFieldView(key, label_key, required, label)`
|Champ proposé ; `#title` : libellé dans la langue courante.

|`ImportRowView(line, cells, action : ImportAction, reference, errors)`
|`line` : numéro de l'enregistrement dans le fichier ; `action` : `Create`,
`Update`, `Refused` (libellés `core.imports.actions.<code>`) ;
`reference` : quick code ou numéro de compte (celui qui sera attribué) ;
`errors` : motifs, rapportés au champ importé.

|`ImportView(fields, columns, header, rows, errors)`
|`errors` : erreurs générales (fichier illisible, champ inconnu ou associé
deux fois, champ obligatoire sans colonne) — aucune ligne n'est alors
traitée. `created_count`, `updated_count`, `refused_count`, `importable?`.
|===

Valeurs lues : décimaux `1 234,56`, `1,234.56`, `1234.56` (jamais de
flottant ; `core.errors.import.decimal`), dates `AAAA-MM-JJ` ou
`JJ/MM/AAAA` (`.date`), booléens `oui`/`non`, `1`/`0`, `yes`, `ja`, `nee`,
`x`… (`.boolean`). Une cellule protégée contre les formules par un export
du cœur (`'+33…`) est relue sans l'apostrophe.

== Fiches (`Partiduo::Api::Cards`)

[cols="3,1,3",options="header"]
|===
|Appel |Droit |Rôle

|`card_import_fields(actor, category_id) : Array(ImportFieldView)`
|`cards.card.import`
|Champs de la catégorie : `name` (exigé, sauf fournisseur), `code`,
`description`, `enabled`, champs de tiers et `address.*` (ou champs
d'article : `unit_code`, `sale_price`, `purchase_price`, `vat_rate` par son
code), `customer_nature`, `supplier_nature`, `last_name`, `first_names`,
`birth_date` selon la nature, `extra.<clé>` pour chaque attribut propre,
`account` si la Comptabilité suit les fiches.

|`preview_card_import(actor, category_id, ImportSource) : ImportView`
|`cards.card.import` et `cards.card.write`
|Aperçu à blanc ; sans en-tête, la première colonne est le nom.

|`import_cards(actor, category_id, ImportSource, skip_refused = false) : Result(ImportView)`
|idem
|Chaque ligne passe par `create_card` (compte demandé : `account`,
`accounting.account.write` exigé) ou `update_card` ; `card.saved` publié
pour chacune.

|`export_cards(actor, category_id) : FileView`
|`cards.card.read`
|Fiches de la catégorie au format de l'import (en-tête de libellés), relues
telles quelles avec `update_existing`.
|===

Refus propres à l'import (`cards.errors.import.*`) : `code_exists` (fiche
existante sans `update_existing`), `other_category`, `account_on_update`
(le compte d'une fiche existante se change depuis la fiche),
`account_forbidden`, `card_unknown` (attribut de type fiche, par quick
code), `vat_rate_unknown`. Un fournisseur sans nature mais avec nom ou
prénoms de personne est une personne physique.

== Plan comptable (`Partiduo::Api::Accounting`)

[cols="3,1,3",options="header"]
|===
|Appel |Droit |Rôle

|`chart_import_fields(actor)`
|`accounting.account.import`
|`number`, `label` (exigés), `parent`, `kind`, `direct_use`.

|`preview_chart_import(actor, ImportSource) : ImportView`
|`accounting.account.import` et `accounting.account.write`
|Sans en-tête : numéro ; libellé ; parent ; type (format d'origine, parent
`0` = aucun). Lignes traitées des numéros courts aux longs : un parent
précède ses comptes quel que soit l'ordre du fichier.

|`import_chart(actor, ImportSource, skip_refused = false) : Result(ImportView)`
|idem
|Par `create_account` ou, avec `update_existing`, `update_account`
(libellé, parent, type, utilisation directe ; le numéro ne change pas, et
la règle du compte mouvementé s'applique).

|`export_chart(actor) : FileView`
|`accounting.account.read`
|Plan entier dans l'ordre de l'arbre, au format de l'import.
|===

Types : code (`asset`…), code d'origine `ACT`, `PAS`, `PRO`, `CHA`, `CON`,
suffixé `INV` pour un compte inversé, ou libellé dans l'une des langues ;
vide : celui du parent. Refus : `accounting.errors.import.number_exists`,
`.kind`, et ceux de la saisie d'un compte. Pas de remplacement du plan
entier (D-OUT-004).

== Archive des pièces (`Partiduo::Api::Accounting`)

[cols="3,1,3",options="header"]
|===
|Appel |Droit |Rôle

|`receipts_archive(actor, date_from, date_to, ledger_id = nil) : Result(FileView)`
|`accounting.entry.read` et `core.attachment.read`
|ZIP des pièces jointes des écritures de la période (journaux visibles, ou
le seul `ledger_id`), nommées `<code interne>-<fichier>`, avec `index.csv`
(code interne, date, journal, pièce, libellé, fichier, SHA-256). Échec
`accounting.errors.receipts.none` sans pièce.
|===

= Société (Settings) et provisionnement
:toc: left
:toc-title: Table des matières
:toclevels: 3
:icons: font
:source-language: crystal

Référence de la configuration société (`Partiduo::Core::Settings`, ligne
unique, héritière de la table `parameter` de NOALYSS), du provisionnement
d'une instance et du point d'accroche du jeu de données initial (ADR-001 D2,
ADR-002 D1). Le contrat est `Partiduo::Api::Core` et
`Partiduo::Api::InitialData`.

== Contrat

[cols="2,1,3",options="header"]
|===
|Appel |Droit |Rôle

|`Api::Core.provisioned?(actor) : Bool`
|authentifié
|L'instance a-t-elle sa société ?

|`Api::Core.settings(actor) : SettingsView`
|authentifié
|La société ; `NotFound` avant le provisionnement.

|`Api::Core.today : Time`
|aucun
|Date du jour dans le fuseau du dossier, à minuit UTC.

|`Api::Core.time_zone : Time::Location` (0.9.0)
|aucun
|Fuseau du dossier : celui de l'instance (`PARTIDUO_TIME_ZONE`,
`Europe/Paris` par défaut, UTC s'il est inconnu). Les horodatages du
contrat (`created_at`, `sent_at`…) sont en UTC ; l'interface les présente
dans ce fuseau, sans quoi un import fait le 13 octobre à 23 h à Paris
s'afficherait au 12.

|`Api::Core.default_locale : String` (0.19.0)
|aucun
|Langue configurée du dossier (`default_locale`), `fr` avant le
provisionnement ou pour une langue non livrée. L'interface en sert les pages
d'un visiteur non connecté dont le navigateur ne demande aucune langue
livrée (D-UI-080).

|`Api::Core.check_settings(actor, SettingsInput) : Result(Nil)`
|`core.settings.manage`
|Contrôle instantané, même règle que la modification.

|`Api::Core.update_settings(actor, SettingsInput) : Result(SettingsView)`
|`core.settings.manage`
|Modifie la société (ligne verrouillée `FOR UPDATE`).

|`Api::Core.provision(Actor.system, ProvisionInput) : Result(ProvisionView)`
|acteur système
|Crée la société et charge le jeu de données initial, en une transaction.
`ProvisionView#invitations` : invitations émises (administrateur), avec le
jeton à transmettre (D-J1-001).
|===

Constantes pour l'interface : `Api::Core::TAX_REGIMES` (`fr`, `be`),
`AUTH_METHODS` (`password`, `passkey`, `federated`), `AUTH_LEVELS` (1..3),
`SESSION_MINUTES` (5..1440).

=== Saisie

`SettingsInput` décrit *la ligne entière* : un champ texte `nil` vaut chaîne
vide, `share_capital` `nil` efface le capital. Les champs à valeur par défaut
(`country_code`, `default_locale`, `domain`, `auth_methods`,
`auth_minimum_level`, `session_duration_minutes`) gardent, s'ils valent `nil`,
la valeur enregistrée — ou prennent le défaut à la création. Les champs
ajoutés au contrat après sa première version (`creditor_identifier`,
`approval_mode`, `approval_reauth_minutes`)
gardent aussi, s'ils valent `nil`, la valeur enregistrée : une saisie
construite avant leur ajout ne les efface pas ; `""` les efface. Pour modifier un
seul champ : `Api::Core.settings(actor).to_input.copy_with(city: "Namur")`.

=== Champs

[cols="2,2,3",options="header"]
|===
|Champ |NOALYSS |Règle

|`company_name` |`MY_NAME` |obligatoire, 255 caractères
|`legal_form` |— |64 caractères
|`share_capital` |— |`BigDecimal`, ≥ 0, 2 décimales au plus
|`rcs` |— |immatriculation (RCS, RPM), 128 caractères
|`siren` |— |régime `fr` seulement ; 9 chiffres, clé de Luhn
|`vat_number` |`MY_TVA` |normalisé (majuscules, sans espace ni ponctuation) ;
préfixe du pays (`EL` pour la Grèce, `FR` pour Monaco) ; FR : clé numérique
contrôlée, SIREN cohérent ; BE : modulo 97
|`street`, `street_number`, `postcode`, `city` |`MY_STREET`, `MY_NUMBER`, `MY_CP`, `MY_COMMUNE` |longueurs
|`country_code` |`MY_PAYS` |ISO 3166-1 alpha-2 ; `fr` : FR ou MC ; `be` : BE
|`phone`, `email` |`MY_TEL` |format de l'adresse
|`tax_regime` |`MY_COUNTRY` |`fr` ou `be` ; *immuable* après création
|`default_locale` |— |`fr`, `en`, `nl`, `de`, `es`, `it`, `pt` (`Partiduo::LOCALES`, 0.19.0)
|`domain` |— |nom d'hôte de l'instance (`<dossier>.<domaine>`)
|`auth_methods` |— |sous-ensemble non vide de `AUTH_METHODS`
|`auth_minimum_level` |— |1 à 3, atteignable par une méthode autorisée
(mot de passe + TOTP : 2 ; passkey, fédérée : 3)
|`session_duration_minutes` |— |5 à 1440
|`creditor_identifier` (0.11.0) |— |identifiant créancier SEPA (ICS,
A-SEPA-2) : forme compacte (pays, clé, code d'activité, identifiant
national ; 35 caractères au plus), clé modulo 97 contrôlée (EPC262) ;
facultatif. Lu par les prélèvements SEPA et les mentions des factures.
|`approval_mode` (0.17.0) |— |`single` (défaut) ou `dual` : validation des
opérations sensibles à une ou deux personnes (A-SEPA-3,
`doc/api/approvals.adoc`) ; `SettingsView#dual_approval?`
|`approval_reauth_minutes` (0.17.0) |— |1 à 60 (5 par défaut) : délai de
l'authentification forte exigée pour approuver
|===

Un changement de `approval_mode` ou `approval_reauth_minutes` est inscrit
à la piste d'audit des approbations (`policy.changed`).

Erreurs : `core.errors.settings.<champ>.<code>` (`blank`, `too_long`,
`invalid`, `regime_mismatch`, `country_mismatch`, `siren_mismatch`,
`not_applicable`, `immutable`, `negative`, `too_precise`, `unknown`,
`out_of_range`, `unreachable`) et `core.errors.provision.…`. Libellés des
champs : `core.settings.fields.<champ>` ; régimes, langues, méthodes et
niveaux : `core.settings.tax_regimes.*`, `locales.*`, `auth_methods.*`,
`auth_levels.level_<n>`.

En base : ligne unique (index `core_settings_single_row` sur `(true)`),
régime, niveau et capital contraints par `CHECK`.

== Tableau en PDF (`table_pdf`)

`Partiduo::Api::Core.table_pdf(actor, TableInput) : Result(FileView)` rend en
PDF/A-2b un tableau déjà mis en forme par l'appelant (listes de l'interface,
ADR-005 D5, B-CRIT-001) : aucune donnée n'est lue, tout utilisateur
authentifié au niveau exigé peut l'appeler.

* `TableInput` : `name` (nom du fichier, assaini), `title`, `columns`
  (`TableColumnInput` : `title`, `kind` `text`/`amount`/`date`/`number`,
  `weight` 0,2 à 10), `rows` (`TableRowInput` : `cells` texte, `style`
  `line`/`heading`/`subtotal`/`total`/`page_break`, `indent` 0 à 10,
  `level` 0 à 3), `subtitle`,
  `landscape` (`nil` : paysage au-delà de six colonnes). 30 colonnes, 20 000
  lignes et 500 caractères par cellule au plus.
* Saut de page et niveaux de titre (0.11.0, A-REP-4) : une ligne
  `page_break` fait commencer la suivante sur une nouvelle page (sans
  effet en tête de page ; ses cellules sont ignorées, et la ligne omise du
  CSV des éditions). `level` d'une ligne `heading` : 0, titre ordinaire en
  gras (comme avant) ; 1 à 3, du plus grand au plus petit, texte de ses
  cellules sur toute la largeur, souligné au niveau 1, jamais seul en bas
  de page. Un niveau sur une ligne qui n'est pas un titre est refusé.
* Refus : `core.errors.table.title.blank`, `.columns.count`,
  `.columns.column`, `.rows.count`, `.rows.row`.
* Rendu commun avec les éditions de la Comptabilité
  (`Partiduo::Core::TableOutput`) : en-tête de la société, titre,
  sous-titres, pied numéroté (`core.exports.page`), polices DejaVu
  embarquées (D-R5-008).

== Jeu de données initial

Chaque pièce (socle, module, extension) déclare ses chargeurs ; seuls ceux des
pièces actives s'exécutent, par `order` croissant, dans la transaction de
`provision`. Un chargeur qui lève annule tout.

[source]
----
Partiduo::Api::InitialData.register("ACCOUNTING", "chart_of_accounts", order: 10) do |context|
  # context.tax_regime ("fr" | "be"), context.country_code, context.locale,
  # context.admin_email, context.module_codes, context.actor (système)
  Partiduo::Api::Accounting.load_chart(context.actor, regime: context.tax_regime)
end
----

Ordres conseillés : 10 plan comptable, 20 taux de TVA, 30 journaux,
40 catégories de fiches, 90 profils et invitation de l'administrateur.

=== Types de dossier (ADR-011 A3)

Un dossier a un *type*, choisi au provisionnement (`ProvisionInput#kind`,
`manage provision --kind`), retenu par la société (`SettingsView#kind`,
`household?`) et jamais modifié. Le cœur déclare :

[cols="1,1,3",options="header"]
|===
|Type |Plan de base |Règles

|`company` (défaut)
|`company` : PCG ou PCMN du régime
|Aucune.

|`household`
|`household` : plan réduit d'un foyer
|La Comptabilité doit être active ; Facturation, Micro-entreprise,
Profession libérale, Stock, Suivi et Analytique ne le peuvent pas
(ADR-011 D2).
|===

Le chargeur `ACCOUNTING.reference_data` lit `context.chart` : le plan réduit
(`src/accounting/data/household_{fr,be}.yml`) porte la trésorerie (compte
courant, livrets, espèces, virements entre comptes), les placements
(assurance-vie, PEA en France, compte-titres), les biens, les dettes et les
catégories de recettes et de dépenses d'ADR-011 D3 (classes 6 et 7) ;
libellés traduits dans la langue du dossier ; un journal financier et un
journal d'opérations diverses ; aucun compte de TVA. Les taux de TVA du
socle restent chargés, inutilisés.

*Accroche des extensions.* Une extension fournit les données initiales d'un
dossier :

[source]
----
# Chargeur limité à certains types (tous si `kinds` est omis).
Partiduo::Api::InitialData.register("PERSO", "categories", order: 30, kinds: ["household"]) do |context|
  # context.kind ("household"), context.chart ("household"), etc.
end

# Type de dossier propre à l'extension : plan de base, modules requis et exclus.
Partiduo::Api::InitialData.register_kind("association", "ASSO", chart: "company",
  required: %w[ACCOUNTING], excluded: %w[MICRO LIBERAL])
----

Un type n'est proposé que si sa pièce est active (`InitialData.kinds`).
Refus de `provision`, champ `kind` : `core.errors.provision.kind.unknown`
(`%{kind}`, `%{kinds}`), `.inactive`, `.required`, `.excluded` (`%{kind}`,
`%{code}`).

== Ligne de commande

`manage provision` (commande Marten, `src/core/commands/provision.cr`) est la
dernière étape de `bin/partiduo-provision` (voir `deploy/README.adoc`) :

[source,sh]
----
PARTIDUO_MODULES=accounting,invoicing crystal run manage.cr -- provision \
  --name="Exemple SARL" --regime=fr --domain=exemple.partiduo.localhost \
  --modules=accounting,invoicing --admin-email=admin@exemple.fr
----

Dossier d'un foyer : `--kind=household --modules=accounting` (ADR-011 A3).

Elle rend compte dans la langue par défaut du dossier, pluriels compris
(`core.provision.modules`, `count:`). Avec `--admin-email`, elle affiche le
lien d'invitation de l'administrateur (`https://<domaine>/invitation/<jeton>`,
valable 7 jours, à usage unique), seul moyen pour lui d'entrer dans une
instance neuve : l'opérateur le lui transmet (D-J1-001).
